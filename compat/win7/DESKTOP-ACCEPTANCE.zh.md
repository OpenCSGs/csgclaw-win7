# CSGClaw Win7 桌面验收

验收日期：2026-10-19。

## TLDR

**已经在 Win7 SP1 x64 中跑通真正的 CSGClaw 桌面 App。**
完整解压交付包后，双击 `CSGClaw.exe` 即可启动窗口和后台服务。
默认工作区沙箱、Codex 对话、交互式终端、文件预览、内置浏览器，以及停止后继续聊天均已通过原生验收。

## 本轮解决的卡点

| 卡点 | 处理方式 | 验收结果 |
| --- | --- | --- |
| 当前桌面运行时及部分 API 无法在 Win7 使用 | 固定 Electron 22.3.27，适配 BrowserView 和导航 API | 真实应用窗口及内置浏览器通过 |
| 系统自带 PowerShell 2 不支持现代环境采集命令 | 使用兼容的对象创建与 JSON 序列化方式 | 真实环境采集返回有效 JSON 和 PATH |
| Win7 高 DPI、小屏幕下发送按钮超出窗口 | 在兼容层按实际视口缩放原布局 | 1024×768、125% DPI 下发送按钮可见且可操作 |
| Win7 缺少现代终端和嵌套 Job 能力 | 使用已验证的 WinPTY 和定制 Codex，保留受限令牌、工作区权限与进程回收 | 中文输入、TTY、越界写入拒绝、取消与超时通过 |
| 桌面退出可能遗留后台 | 保留桌面与 Go 的控制通道，使用实际进程句柄检查退出 | 应用拥有者退出后 Go 自动回收 |

CSGClaw 根目录与上游 `80d920a1` 保持一致。
适配代码、补丁、冻结依赖、构建入口及测试均放在 `compat/win7`，不移动业务目录。
Go 使用专用 Win7 工具链，业务依赖和 vendor 不降级。
Codex 固定为 `0.149.1` 加可独立维护的 Win7 补丁。

页面取消验收持有并核对了真实父子进程的句柄和可执行文件路径。
点击 Stop 后两个句柄均进入退出状态，随后取消结果落库，输入框恢复可用，原会话成功返回 `WIN7_DESKTOP_CANCEL_RECOVERED`。
没有通过重启应用、刷新页面或放宽沙箱权限完成该项验收。

测试环境为 Apple Silicon 上 UTM 5.0.7 的 x86 CPU 模拟虚拟机，Win7 Ultimate SP1 x64，4 GB 内存、1 个虚拟 CPU。
模型服务经主机中继连接真实服务。
冷启动和部分对话耗时较长，本轮证明功能闭环，不构成真实 x64 硬件上的性能验收。
机器可读记录及原始日志指纹见 `desktop-verification-20261019.json`。
此前 Web/API 功能矩阵保留在 `verification-20261017.json`，其中明确未验收的项目不能视为本轮新增通过。

## 交付与边界

交付形式为完整便携目录和 ZIP，用户只需解压并双击 EXE，不需要手工启动服务。
此版本为 `0.8.0-win7.dev.1` 开发验证包，尚未制作签名安装器或接入正式发布流水线。
普通 Windows 自动更新渠道关闭，后续升级须使用匹配的 Win7 包。

本次通过范围为 **Electron 桌面壳及 Go + Codex**。
DSH 的独立 Node 运行时仍单列适配；Electron 内置 Node 不能替代该项验证。
第三方服务、账户登录、MCP 和外部工具依然受其网络、凭据及兼容依赖约束，没有宣称全部外部服务都已通过。
BoxLite 沿用现有 Windows 版基线。

## 结论

**CSGClaw 兼容 Win7 已具备可运行、可构建、可维护的实现，并完成桌面核心闭环验收。**
本次没有为跑通 Go + Codex 桌面链路删除业务功能或关闭默认工作区沙箱。
后续可按同一目录结构持续合并上游更新，并通过独立 Win7 构建和原生验收维护兼容版本。
