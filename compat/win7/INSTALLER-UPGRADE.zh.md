# 安装和升级

同一个安装包支持首次安装、覆盖升级和同版本修复，不需要先卸载旧版。
构建入口只交付安装 EXE、SHA-256 和构建记录，不生成运行版 ZIP；`dist/win7/app` 仅为安装器的中间输入。
安装包、安装向导和系统卸载列表使用构建日期与应用源码真实 commit 标识，例如 `CSGClaw-Win7-x64-20261020-070609b4-Setup.exe`。
包内 `win7-build.json` 分别记录应用与安装器源码信息，重新封装旧应用不会把安装器当前 HEAD 冒充成应用 commit。
正式分发要求已提交的兼容源码和干净的应用构建；`--allow-dirty` 仅供本机验收，并强制给名称添加 `dirty`。
Windows 的数字文件版本使用日期和当日分钟数，应用内部版本仍保留在构建记录中。
安装器编译成功后才发布最终 EXE，编译失败不会用不完整文件覆盖已有安装包。

安装器通过已有安装注册自动沿用原目录，显示当前和待安装构建。
相同源码 commit 允许修复安装；源码提交时间早于当前安装的构建会要求确认降级，静默安装默认拒绝降级。
尚未记录提交时间的早期安装包仍允许升级，不能据此承诺自动识别它与任意新包的先后关系。
便携版目录不自动接管，避免覆盖用户手动放置的程序。

升级前须从托盘退出 CSGClaw，并等待其后台程序退出。
安装器会阻止同时运行多个安装器，遇到占用的程序文件时停止并提示。
新程序先解压到安装目录旁的专用升级目录并校验文件摘要，随后仅替换安装器所属的程序文件。
旧清单中已经淘汰的文件会移除；用户自建文件、用户配置、登录状态、聊天记录和工作区不会列入替换清单。
若新程序路径与用户自建文件冲突，安装器报错而不覆盖该文件。

替换过程在同一磁盘保留旧文件和恢复日志，替换失败时恢复原版。
安装器被强制结束后，再次运行安装包会先恢复未完成的文件事务，再开始安装。
恢复受文件占用等因素阻碍时会明确报错并保留升级目录，不能手动删除这个备份目录。
这项保护针对程序文件安装，不回滚应用启动后进行的配置或数据库迁移，因此降级仍需谨慎。

## 原生验收

`installer/` 是标准库实现的独立安装事务辅助程序，使用与应用相同、已锁定的 Win7 Go SDK 构建。
`installer/main_test.go` 验证旧文件清理、用户文件保留、各替换边界失败恢复、子进程强制退出后的恢复、摘要损坏和文件冲突。
测试可在主机执行，也可编译为 Windows 测试程序后直接在 Win7 执行。

`tests/upgrade/build-fixtures.py` 构建基于原安装器和当前生产 NSIS 脚本的小型原生安装夹具。
夹具使用独立产品 ID、安装目录、快捷方式与卸载注册，不修改正常 CSGClaw 安装。
原生场景覆盖运行占用拦截、旧安装包升级、自动发现目录、同版本修复、拒绝静默降级、用户文件保留和卸载。
这些夹具只验证安装流程，不替代完整 CSGClaw 应用的聊天和 Manager 验收。
