# Win7 Manager 离线与自动恢复

## 结论

首次没有可用模型可能留下未完成的运行时，但尚未证实这是远程测试机最初失败的原因。
已确认的恢复缺口是：界面阻止向离线 Agent 发消息，后台也没有在对话开始时应用遗留的待重建配置。
Manager 未保存运行意图时，还可能把运行失败误当成停止意图。

本轮改为：发送消息时，若 Codex 已离线、模型配置完整、期望运行且存在待重建配置，则先通过原有生命周期流程恢复，再继续对话。
恢复保留工作区和会话，不删除 Agent，也不反复重建正在运行的实例。
手动停止、缺少模型和连接器配置未完成时仍保留真实错误，不绕过检查或伪造在线状态。

## Win7 停止流程

已在实际 App 中复现保存配置返回 `codex app-server stop timeout after 3s`。
Go 栈显示退出回调停在覆盖运行元数据的文件截断操作，旧进程清理因而未能及时完成。
Win7 专用实现以完整文件替换元数据，并协调同一路径的读写；退出清理等待上限调整为三十秒，调用方取消仍有效。
替换会话前仍等待旧进程和退出状态提交完成，默认工作区沙箱保持启用。

关闭窗口的临时变动已撤回，仍使用原来的关闭到托盘和托盘 Quit 完整退出方式。
主仓库业务目录保持原样，全部适配位于 `compat/win7/`，仅覆盖隔离构建树。

## 验收证据

- UU 远程确认 Manager 显示离线、已配置、需要重建，发送前被界面阻止。
- 前后台回归覆盖离线恢复、后续对话复用、缺模型、手动停止和连接器未就绪。
- 原生 Win7 验证元数据并发读取、退出提交、调用方取消，以及默认沙箱的执行、取消、超时、后台任务和拥有者崩溃回收。
- 本机 Win7 真实 App 在运行中注入 Manager 故障和待重建标记后，不重启 App 即获得真实模型回复 `WIN7_MANAGER_AUTO_RECOVERY_OK`。

上述 App 证据来自本轮候选后台，不能代替任意后续重新构建的安装包验收。
构建身份以包内 `win7-build.json` 为准，原始结果位于忽略目录 `.cache/win7/manager-offline-20261020/`。
UU 远程测试机尚未更新本轮修复，不能将本机验证描述为远程测试机已经修复。
